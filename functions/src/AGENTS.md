# Article and Voting Function Guide

All Firebase Functions in this directory are decommissioned. Treat the files as migration reference only; implement production changes in `supabase/functions/`.

- Keep article processing in `createAdminArticle.ts` and voting in `voteDiscussionTopic.ts`; both use the Admin SDK and must validate all callable inputs.
- Article figures must not enter any Vertex model request. Generated covers are stored in Firebase Storage and published only after successful generation.
- Vote aggregates belong in `article_discussion_stats`; individual votes belong in `article_discussion_votes`. Update both only inside the server transaction and preserve one record per user/topic.
- Payment attribution may accept only a validated growth tracking code. Persist it on the source payment order and increment `growth_posts.metrics.signups` at most once per source order inside a transaction after a successful initial payment.
- `marketingCron.ts` owns Gopas scheduling. It uses a fixed five-minute `onSchedule` trigger plus a server-calculated Firestore `nextRunAt` from the saved KST minute, hour, and weekdays, and an Admin-SDK transaction lease, so timing edits take effect without a function redeploy and overlapping Scheduler invocations cannot post twice.
- The schedule config stores a template ID for manual runs and a `templateAssignments` map for scheduled weekdays. Resolve the assigned saved template inside the server transaction and snapshot it into the run; never trust browser-supplied copy or destination data for a scheduled post.
- `ensureDefaultMarketingTemplate` seeds the original Gopas advertising copy, a Sunday-countdown title token, and its existing image URL into the fixed template ID. Never add the source script's credentials or any Gopas login secret to this codebase. Photo URLs are validated, passed to the publisher, and rendered as escaped linked HTML before the post body.
- Treat an explicit empty saved weekday list as a disabled schedule; do not restore defaults for it. Resolve `{{daysUntilSunday}}`/`{daysUntilSunday}` in title, copy, and CTA immediately before a run. It is deterministic date formatting, not an AI-agent task.
- Before a Gopas publish attempt, check the current first page of `freead` for the normalized title. On a match, write a `skipped` run with the content/performance snapshot, clear the lease, and do not create a tracking post. An unavailable duplicate check must fail open, matching the original workflow.
- Do not add Gopas credentials to the repository. The optional server-only publisher webhook is configured through `KOREAPAS_PUBLISHER_URL` and `KOREAPAS_PUBLISHER_TOKEN`; it receives `publish` and `performance` actions. Without it, runs must remain `awaitingPublisher` rather than claiming a post was published.
